【任务】3 个文件（**一个都不许多**）：
  A) 改 scripts/ingest/collector_pull.py（**逐文件事务**，修原子性缺陷）：
     现状缺陷：run() 用调用方给的**一个连接一个事务**处理整批文件，但 `shutil.move` 是文件系统操作、不随事务回滚 →
       若第 2 个文件抛异常，第 1 个文件的 stg/ops 写入被回滚，可它的原件已经被移进 done/ → **数据没了也没留痕**（只能靠采集机 30 天副本重推）。
     改成：**每个文件一个独立事务**，且"先提交、后归档"——
       for marker in pending(incoming): data = ...; with conn.transaction(): { load_file + file_arrival + ingest_log }   # 提交成功
       再执行 _archive(...)                                                                                        # 然后才动文件
     语义要求：① 单文件异常不得中断整批（catch 该文件、写 ingest_log(ok=false, rejected 带 reason) 并把原件送 bad/，然后继续下一个）；
       ② 装载失败时文件必须原地不动或进 bad/，绝不能"DB 无记录 + 文件消失"；③ 重跑同文件靠 stg.src_hash 幂等，不产生重复行。
  B) 同文件里修"未知 topic 永久滞留"死角：
     现状：topic 不在 STG_TABLES 且带 .done 的文件只 logger.warning + continue → 每轮重复告警、永远堆在 incoming/。
     改成：这类文件（连同其 .done）归档到 `bad/_unknown/<原相对路径>`，并写一行 ops.ingest_log(topic=<那个目录名>, ok=false,
       rejected=[{"reason":"unknown topic"}])；`collector.status.json` 这类**没有 .done 的文件保持不动**（新鲜度监控要看它）。
  C) 新增 tests/test_quota.py（≤100 行）常驻用例覆盖 quota 的**两条越界路径**（上一单只在一次性脚本里试过，没落成用例）：
     ① 已有 used=cap 时再 charge → 抛 QuotaExceeded 且账本不变；② n > cap（当日首行、插入路径无 WHERE 守卫）→ 抛 QuotaExceeded；
     ③ remaining 在无行时返回 cap、有行时返回 cap-used；④ 抛异常后同一连接仍可继续用（事务未被污染）。
     铁律：全部写入留在事务里收尾 ROLLBACK；连不上库 → pytest.skip 带原因，不许 fail。
