【为什么要改身份键（真跑 P0-MODEL1 才暴露，全量测试当时是绿的）】
  身份键原本是 `name_cn = core.i18n.to_cn(源队名串)`，而 ① **API-Football 跨赛季会改队名拼写**（"Vfl Bochum"→"VfL Bochum"、"Bayern Munich"→"Bayern München"）
  ② `to_cn` 按字符串查词典，换了串就可能翻不出来 ⇒ 同一家俱乐部（AF id 一模一样）被插成两行。
  后果：按 (league, season) 拟合时"上一季没这支队"⇒ **德甲 2024 季 306 场只写出 132 场预测（跳过 57%）**。
【现状＝本单的硬闸】索引一上，`tests -q` 当场 **1 failed, 389 passed**：
  `tests/test_align.py::test_fd_block_merges_into_af_fixture_only` →
  `UniqueViolation: duplicate key value violates unique constraint "team_af_key"  Key (sport, af_id)=(football, 990010003) already exists`
  根因：`_af_body()` 造队时 **AF team id 是从 fixture 哨兵 id 推出来的**，于是"两个测试文件各自的哨兵场"共用上了同一个俱乐部 id，
  而两处给的队名串不同（一处默认名、一处 `"Inter"`）⇒ 老代码走 `ON CONFLICT (sport, name_cn)` 当作"新俱乐部"插第二行。
  **这不是索引错了，正是索引抓到了真 bug**（真数据里拜仁就是这么被拆成两行的）。修的方向是"按 id 认队"，**不是**把索引拆了。
