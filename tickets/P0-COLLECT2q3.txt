【A. 现状（照抄，别去查）】
 `_from_manifest(root, man, topics)` 现在长这样（语义顺序就是问题所在）：
```
 for topic in topics:
     if topic not in man:
         out[topic] = [(None, "missing")]        # ← 先判缺档
         continue
     out[topic] = [_check_entry(topic, root / rel, decl) for rel, decl in man[topic]]
 for rel, decl in man.get("", []):               # ← 后才消歧并入
     hit = _resolve(root, topics, rel, decl)
     if hit:
         t, p = hit
         out.setdefault(t, []).append(_check_entry(t, p, decl))
```
 · `man` 的键：带 `topic/` 前缀的行按 topic 归；**丢了前缀的行全在 `man[""]`**（2q1b 的设计）；
 · ⇒ 对方从 `01-13` 批起**整批都丢前缀** ⇒ `man` 里**只有 `""` 一个键** ⇒ 上面第一段循环把**七个 topic 全部判成缺档**，
   第二段虽然把数据认领进库了（实测每批 `ups=49` ✔），**gap 行却还是写了** ⇒ 队长 10:52 实测 `ops.file_arrival` 假 gap **8 → 85**。
【B. 唯一允许的改法（**先消歧完，再一次判 missing**；不许换结构）】
 1) **先**遍历 `man.get("", [])`，调 `_resolve()`，把命中的收进 `resolved: dict[str, list[tuple[str, int]]]`（**存 rel/decl，别存绝对路径**）；
 2) **再**遍历 `topics`：`entries = man.get(topic, []) + resolved.get(topic, [])`；
    · `entries` 为空 ⇒ `out[topic] = [(None, "missing")]`；
    · 非空 ⇒ `out[topic] = [_check_entry(topic, root / rel, decl) for rel, decl in entries]`；
 3) 消歧**没命中**的 rel（`_resolve` 已打过 `manifest-无法消歧`）⇒ **什么都不做**：不许造 gap、不许凭空认领。
 ⚠️ 净增行数 **≤ 1**（`jc_read.py` 最多 100 行）。做不到就**停下贴 `wc -l`**，别压别人的函数、别删注释硬挤。
