【任务】4 个新文件（**一个都不许多**）：
  1) scripts/ingest/api_get.py     ≤100 行  统一"取一次远程 → 落 raw 块"的最小内核
       · `params_hash(source, endpoint, params) -> str` = `sha256(endpoint + "?" + urlencode(sorted(params.items())))`（**排序规范化**，同一逻辑请求必须得同一键）
       · `cached(conn, table, params_hash) -> dict | None`：命中即返回已存 body，**不发请求、不扣配额**（`league_ing` 无 UPDATE，重复插会撞 UNIQUE，故先查后插 + `ON CONFLICT (params_hash) DO NOTHING` 双保险）
       · `fetch(conn, *, source, table, endpoint, params, cap) -> dict`：查缓存 → 未命中则**先 HTTP 后扣账**（见下条顺序理由）→ 落块 → 返回 body
       · **写库顺序**：HTTP 成功后必须先 `quota.charge(...)` 再 INSERT raw（若 INSERT 失败要 `logger.error` 明说"配额已花、原始响应未落块、重跑会再花 1 次"，绝不静默）
       · **失败也落块**（`http_status` 记真值、`body` 存原始 JSON 或 `{"_error": "..."}`）：防"坏请求被反复重试烧配额"；解析侧一律先按 `http_status==200 AND errors==[]` 过滤
       · 传输只用 stdlib `urllib.request`（**禁用 requests/新依赖**）；重试：仅**网络异常/5xx**退避 `5/15/45s` 三次；`429`/`401/402/403/404` **绝不重试**（429 重试只会更糟）；超时用 `core.constants.TIMEOUT_API_FOOTBALL`
       · `QuotaExceeded` 必须原样向上抛（这是"今天到此为止"的信号，编排层靠它收尾）
  2) scripts/ingest/run_backfill.py ≤100 行  回填编排（CLI，`python -m ingest.run_backfill`）
       · 计划集 = `LEAGUE_CONFIG` 里 `api_football_id` 非 None 的五联赛（epl=39 / laliga=140 / bundesliga=78 / seriea=135 / ligue1=61）× season `2022,2023,2024` → AF 15 条；
         FD 用同一张表的 `league_id` 字段（实测值：**PL / PD / BL1 / SA / FL1**，别自己编代号）× 同三季 → 15 条
       · `--plan` 只读：打印每条 `source league season 待取/已有`（用 `cached()` 判定）+ `quota.remaining`；**一条 HTTP 都不许发**
       · `--execute --limit N`（N 默认 10，硬上限 20）：只发"待取"的，逐条 api_get.fetch；**FD 两次请求之间 `time.sleep(7)`**（免费档 10 req/min，实测 6.1s 会 429）；`QuotaExceeded` → 打印"今日到此为止"并 `return 0`（**这是正常收尾不是错误**）；其它异常 → 记 log 并 `return 1`
       · `--source af|fd|all`（默认 all）；`--seasons 2022,2023,2024` 可覆盖
  3) tests/test_backfill_transport.py ≤100 行  **假 transport，零真网络**（monkeypatch `api_get.urllib.request.urlopen`）
  4) tests/test_backfill_plan.py       ≤100 行  计划生成 + 幂等 + limit，**零真网络**；需要 DB 的用例一律走"单事务收尾 ROLLBACK"（`league_ing` 没有 DELETE，留了洗不掉），连不上库则 `pytest.skip` 带原因
【必须被测试钉死的行为】
  A. 同一 (endpoint, params) 第二次调用：**假 urlopen 调用次数 == 0**、配额**不再增加**、返回同一 body（顺序无关的 params dict 也必须命中同一 hash）
  B. 非 2xx / `errors` 非空：仍落 raw 块（`http_status` 真值），且第二次调用**不再发请求**（坏请求不重烧配额）
  C. 5xx：退避重试 3 次（用假 sleep 断言等待序列 `[5,15,45]`，**不许真 sleep**）；429/401：**只发 1 次**、不重试
  D. `charge` 越界 → `QuotaExceeded` 原样抛出，且此时**不应已发 HTTP**（预检语义）
  E. 计划：AF 15 条 + FD 15 条、五联赛齐全、`nba` 不出现（其 `api_football_id` 为 None）；`--limit 3` 只发 3 条
  F. 端点形态（**照此拼，别改**）：AF = `https://v3.football.api-sports.io/fixtures?league={id}&season={s}`（header `x-apisports-key`）；

     两源 params 都只放 `league/season` 或 `competition/season` 这类**逻辑参数**，别把 key 塞进 params（会进 raw.body 邻接列与 hash）。
