# P0-TEAMMIX1 — 西甲 AF 侧「同一家俱乐部两行」的防重与补键

> ## ⚠️ 2026-09-16 决策更新（用户批复 **C = 接受缺口**）
> 本单原先假设「先拉 AF 西甲 → 再合并重名行」。**该路径已关闭**：
> `run_backfill.py --execute --seasons 2026 --source af` 五条全 HTTP 200，但每块 body 都是
> `{"errors":{"plan":"Free plans do not have access to this season, try from 2022 to 2024."}}`
> ⇒ **AF 免费档硬限 2022–2024 赛季**，当前赛季要付费档。用户选 C：不买付费档、不拉次级联赛、
> 接受 4 支降级队（拉科鲁尼亚/桑坦德竞技/莱万特/马拉加）无 AF 历史。
> ⇒ **合并 SQL 永远不会有命中，本单不再产出 SQL，改只读核查 + 留档。**
>
> ## ★新增发现（2026-09-16 实测）：竞彩侧同一家俱乐部有两个 sporttery id
> ```
> 皇家马德里  id=2350   af=541  jc=664  aliases={"sporttery":"664","api_football":541,"football_data":86}
> 马德里竞技  id=120507 af=NULL jc=172  aliases={"sporttery":"172"}
> ```
> `fact.jc_match` 实测：`home_sporttery_id=172` 时队名「马德里竞技」；
> `away_sporttery_id=664` 时队名「皇家马德里」——**采集机自己用两个名字指同一家俱乐部**。
> ⇒ 这不是能靠合并解决的问题：`aliases->>'sporttery'` 是单值，一行只能持一个 id，
> 合并等于丢掉另一个 id 对应的那部分比赛（`jc_id` 生成列也只取一个值）。
> 真正修法是 schema 支持一队多 jc id（DDL，另开工单）或采集机统一队名口径（采集机侧）。
> **本单不碰这两件事，只把事实留档。**
>
> 顺带：库内无法模糊检测同类情况（`ref.team` 无 AF 原名列，只有 `name_cn`+`aliases`；
> 按 `name_cn` 分组查不到，因为两个名字字符串不同）。这类问题的检测需要队名归一化，
> 属 `store/team_identity.py` 的 `resolve_team` 范畴，不在本单。


## 背景（19:20–20:30 实测，全部来自本库，无猜测）

## 核查结果（队长 2026-09-16 亲自执行，实跑 `core.i18n.to_cn`）

`to_cn` 实现 = `COUNTRY_CN` 查表 → `load_translations()` 读本地 JSON 缓存 → 都没有就**原样返回**。
`load_translations` 只读 `TRANSLATION_CACHE_FILE`，无网络、无 LLM 调用（`scripts/core/i18n.py:20`），
所以本核查零副作用。

### 结论（与 C 决策一致，无需动作）
